# Lab: User role can be modified in user profile

[中文](./01-user-role-can-be-modified-in-user-profile.zh-CN.md) | **English**

## 1. Lab Information

- Platform: PortSwigger Web Security Academy
- Module: Access Control
- Difficulty: Apprentice
- Vulnerability Type: Vertical Privilege Escalation / Broken Access Control
- Keywords: roleid, JSON tampering, hidden field, privilege escalation

---

## 2. Vulnerability Background

This lab demonstrates a broken access control issue in a user profile update function.

The application allows a normal user to submit a sensitive privilege-related field, such as `roleid`, in the profile update request. If the backend directly trusts this user-controlled field, an attacker can escalate their privileges from a normal user to an administrator.

---

## 3. Testing Methodology

After logging in as a normal user, inspect the request generated by the profile or email update feature.

Key points to check:

- Does the response contain fields such as `roleid`, `isAdmin`, or `permission`?
- Can these fields be added manually to the JSON request body?
- Does the backend accept and apply the modified role value?
- Can the user access administrator functions after modifying the field?

---

## 4. Key Request

```http
POST /my-account/change-email HTTP/2
Host: vulnerable-site.web-security-academy.net
Cookie: session=[REDACTED]
Content-Type: application/json

{
  "email": "test@example.com",
  "roleid": 2
}
```

---

## 5. Exploitation Process

1. Log in as a normal user.
2. Update the email address and capture the request in Burp Suite.
3. Send the request to Repeater.
4. Add the `roleid` field to the JSON body.
5. Send the modified request.
6. Access the administrator panel.
7. Use the newly obtained administrator privilege to complete the lab objective.

---

## 6. Root Cause

The backend trusted a user-controlled privilege field.

Privilege-related fields such as `roleid`, `isAdmin`, or `permission` should never be accepted from a normal user's request.

---

## 7. Remediation

- Do not accept privilege-related fields from normal user requests.
- Use a server-side allowlist for editable profile fields.
- Only administrator-only endpoints should be allowed to change user roles.
- Enforce authorization checks on the server side.
- Log and audit all role changes.

---

## 8. Summary

The key lesson is:

> Hidden fields are not security controls. Any sensitive field submitted by the client must be treated as untrusted.
